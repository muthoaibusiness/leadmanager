# WECON Public Project — Latest Build Plan

## 1. Objective

Build a public, shareable WECON project page. Visitors do not need to log in.

Keep scope deliberately small: project information, floor plan, brochure, and an interactive unit map with live availability statuses.

## 2. Customer Journey

## 3. Functional Requirements

### 3.1 Public Project URL
- Provide one public URL per project.
- Allow anyone with the link to open the page without signing in.
- Ensure the page works on mobile and desktop.
- Use a stable, readable URL slug where supported by the existing application.

### 3.2 Project Details
Display:
- Project name and approved project information.
- Floor plan.
- Brochure link or PDF viewer/download.

Only display information and files available in the existing project data. Do not invent missing property details.

### 3.3 Interactive Unit Map
- Display the project floor plan with selectable units.
- Visually distinguish these three statuses:
  - **Available** — selectable.
  - **Booked** — visible but unavailable for selection.
  - **Sold** — visible but unavailable for selection.
- Include a clear status legend.
- Make unit status understandable without relying on color alone; include text or another visual cue.
- Support touch interaction on mobile and pointer interaction on desktop.

### 3.4 Unit Details
When a visitor selects an **Available** unit, show:
- Unit identifier/name.
- Current availability status.
- Unit details that exist in the connected data source.

Do not add a booking form, lead form, agent assignment, WhatsApp integration, or analytics in this scope.

For **Booked** and **Sold** units, do not open the selectable-unit detail flow. Keep them visibly marked as unavailable. If the existing design already supports a read-only detail view, it may be retained, but do not build extra behavior unless requested.

## 4. Data and Integration
- Use the existing Weppro CRM as the intended source for project/unit data, subject to verifying its current API and data access.
- Before implementation, inspect the repository and identify the existing framework, conventions, and data model.
- Do not assume Weppro has an API or invent endpoints, credentials, fields, or response formats.
- If CRM access is not yet available, use a clearly isolated mock-data adapter for local UI development. Do not represent mock data as live CRM data.
- Keep availability rendering driven by a single normalized unit-status field.

Suggested status values:
- `available`
- `booked`
- `sold`

Map CRM values to these internal values only after confirming the actual CRM schema.

## 5. Suggested Page Layout

1. Project header and project information.
2. Floor-plan section.
3. Unit status legend.
4. Interactive floor plan/unit map.
5. Brochure view/download link.
6. Selected available unit details panel.

The floor plan and unit map may share one visual area if the current assets and architecture support it.

## 6. Implementation Sequence

1. Inspect the repository and existing app architecture.
2. Identify the source of project, floor-plan, brochure, and unit data.
3. Verify Weppro CRM API/data access before integration.
4. Implement the public project page and responsive layout.
5. Render the floor plan and interactive unit overlays.
6. Implement status-aware selection:
   - Available: selectable; show unit details.
   - Booked: disabled/unavailable.
   - Sold: disabled/unavailable.
7. Connect real data where confirmed; otherwise isolate mock data behind an adapter.
8. Add loading, empty, and error states.
9. Test desktop/mobile layouts, keyboard accessibility, status rendering, and public access.
10. Document configuration requirements and any integration blockers.

## 7. Acceptance Criteria

- [ ] Public project page opens without login.
- [ ] Page displays available project information.
- [ ] Floor plan renders correctly.
- [ ] Brochure can be opened or downloaded.
- [ ] Unit map clearly shows Available, Booked, and Sold.
- [ ] Available units can be selected.
- [ ] Selecting an Available unit displays its identifier, status, and available details.
- [ ] Booked units cannot be selected.
- [ ] Sold units cannot be selected.
- [ ] Status labels remain understandable without color.
- [ ] Layout works on mobile and desktop.
- [ ] No booking form, CRM workflow, WhatsApp integration, or analytics is added.
- [ ] CRM integration is not claimed as live until verified and tested.
